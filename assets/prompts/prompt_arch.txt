# Summary

The request presents a detailed specification for creating an architecture diagram for a demo that measures how well a Netomi virtual agent, helped by an external detection service, can tell an AI agent from a person in a customer-service chat. Everything except the virtual agent runs on one laptop. A Jupyter notebook drives a harness whose simulated customer is a small local model on Ollama. The harness reaches the agent in one of two ways: straight through the Netomi Chat API with no web page (Levels 1–2), or by driving a real browser with Playwright to a demo page that carries the Netomi chat widget and a telemetry collector (Levels 3–6). Recorded human testers use the same page. The collector posts keystroke timing, mouse movement and browser flags to the detection service, and the virtual agent calls the detection service's two MCP tools on every turn through a single ngrok tunnel.

**Primary Focus:** Visualize two places, the Netomi cloud and the laptop, and the paths between them: the two ways a customer reaches the agent (Chat API, or the widget on the demo page), the page's telemetry going to the detection service, and the agent's tool calls coming back out through the tunnel to that same service. The reader should see at a glance that the detection service sits where two streams meet: what the page saw (telemetry) and what the agent asks (tool calls), and that the Chat API path skips the page and its telemetry entirely. The reader should also see that the AI customer is a model running locally on the laptop, inside the laptop boundary and labeled as local, not a cloud service.
